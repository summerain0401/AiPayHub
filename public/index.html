三步上手

几分钟搞定，不用等几周。

01

创建支付网关

粘贴你的 AI 接口地址，设个单价，点一下生成。你会得到一个公开网关 ID 和私有管理密钥。无需注册、无需实名、无需营业执照。

02

替换接口地址

把原来的 API 地址换成网关代理地址。任何用户首次请求都会收到 HTTP 402 和支付链接。你的原始接口始终隐藏在后端。

03

收款、放行、流式响应

用户用支付宝完成支付，Webhook 回调标记订单已付。用户拿着订单令牌重试请求，网关放行转发，流式返回 AI 结果。响应完成后订单即焚，零重放风险。

接口流程

同一个请求地址，两种返回结果。

# 首次请求：未支付
POST /gw_x7k2m/v1/workflows/run
402 Payment Required
paymentUrl: /pay/ord_b8f2

# 支付宝 X402 支付后：
POST /gw_x7k2m/v1/workflows/run
X-Order-Id: ord_b8f2
200 OK (streaming)
data: {"text":"Here is your analysis..."}

# 响应完成后订单即焚
# 同一 Order-Id 重用 → 402 已过期
核心特性

为 AI 创作者而生，不为银行设计。

免登录密钥对鉴权

告别密码、邮箱验证和 OAuth。你会拿到一个公开网关 ID 和一个管理密钥。把密钥粘贴到看板就能看到实时收入。这就是全部的鉴权系统，没有多余的环节。

HTTP 402 + X402 协议

标准的 HTTP 402 Payment Required 响应。AI 智能体自动识别、触发支付宝 X402 支付、重试请求。智能体对智能体的秒级结算。

阅后即焚

每个订单令牌只能用一次。上游 AI 响应传输完成后，订单立即从 Redis 中删除。无法重放攻击，无法重复扣款。

全透明代理

你的原始 API 地址始终隐藏在后端。网关透明转发请求、流式透传响应，支持 SSE 和 WebSocket。用户只看到网关地址，看不到你的服务器。

适用场景

一个网关，四类用户。

Dify / Coze 搭建者

将 OpenAPI Schema 导入为自定义工具。工作流自动获得"创建账单"和"校验状态"两个节点。拖拽、连线、变现，零代码。

MCP 服务器作者

将你的 MCP 端点接入网关。用户按次付费调用。你的服务器始终隐藏在代理后端，流式响应原封不动透传。

技能包创作者

将 .cursorrules 和 Markdown 技能包放在内容锁后面。用户未付费时只看到付款提示，付费后收到完整内容一次，随后销毁。

社群运营者

基于 Webhook 的访问控制，适用于微信、Telegram、Discord 机器人集成。按用户计费，无需管理用户账号体系。
